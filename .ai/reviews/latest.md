# Review — Latest

The Reviewer fills this file in per task, replacing the template below.
This file belongs to the Reviewer — the Implementer does not edit it.

The Reviewer's core job is independent verification: take each claim in
`implementation-result.md`, find the evidence in the actual diff or test output,
and mark it `VERIFIED`, `PARTIALLY VERIFIED`, `UNVERIFIED`, or `FALSE`. Then
issue a verdict.

#### Verdict

One of:

- **APPROVED — READY_TO_MERGE.** All acceptance criteria met, all claims verified or non-blocking-unverified, conventions followed. Implementer may merge (or user merges).
- **REVISIONS_REQUESTED.** Blocking findings listed above. Implementer: fix each, update `implementation-result.md`, and set `state.md` back to `IMPLEMENTATION_DONE — PENDING_REVIEW`.
- **ESCALATED.** A judgment call the Reviewer and Implementer cannot resolve. See `state.md` `## Escalation to user`.

#### Next step

The single concrete next action.

- Implementer merge and delete the feature branch, OR
- Implementer revise per blocking list above, OR
- User decides on the escalated question in `state.md`.
